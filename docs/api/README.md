# API 명세

다이소 프로젝트의 API 공통 규칙과 기능별 명세를 정리합니다.
아직 합의하지 않은 항목은 `미정`으로 표시하고, 팀 합의 후 갱신합니다.

## 공통 규칙

| 항목 | 내용 |
| --- | --- |
| 서버 주소 | 미정 |
| API 기본 경로 | 미정 |
| 인증 방식 | 미정 |
| 요청·응답 Content-Type | 미정 |
| 날짜·시간 형식 및 시간대 | 미정 |
| 페이지네이션 방식 | 미정 |

## 공통 응답

### 성공 응답

응답 본문 구조와 HTTP 상태 코드 사용 기준은 미정입니다.
응답 본문이 없는 경우의 처리 방식도 함께 합의합니다.

### 에러 응답

에러 응답 구조, 에러 코드, HTTP 상태 코드 사용 기준은 미정입니다.
입력값 검증 실패와 인증·인가 실패 시 응답도 함께 정의합니다.

공통 응답과 예외 처리 방식의 결정 이유는 [ADR](../adr/README.md)에 기록합니다.

## API 목록

아직 등록된 API가 없습니다. 기능과 경로가 확정되면 아래 표에 추가하고 상세 명세를 연결합니다.

| 기능 | 메서드 | 경로 | 상세 명세 | 상태 |
| --- | --- | --- | --- | --- |

상태는 `작성 중`, `합의 완료`, `구현 완료`로 구분합니다.

## 명세 작성 규칙

- 기능별 Markdown 파일을 `docs/api/`에 작성하고 API 목록에 링크를 추가합니다.
- 각 API에는 다음 내용을 포함합니다.
  - API 목적, HTTP 메서드와 경로
  - 인증 필요 여부와 요청 헤더
  - 경로 변수, 쿼리 파라미터, 요청 본문의 타입·필수 여부·제약 조건
  - 요청 예시와 성공 응답 예시 및 HTTP 상태 코드
  - 발생 가능한 에러 상황, 에러 코드 및 HTTP 상태 코드
- 공통 규칙과 다른 동작이 있다면 해당 명세에 명시합니다.
- 명세가 바뀌면 프론트엔드와 변경 내용을 합의하고 관련 구현과 문서를 함께 갱신합니다.
- 예시에 실제 비밀번호, 인증 토큰 등 비밀 정보를 넣지 않습니다.

## 외부 명세

Swagger 또는 별도 API 명세 도구 사용 여부와 링크는 미정입니다.
사용이 확정되면 최신 명세를 관리하는 위치를 이 문서에 명시합니다.
