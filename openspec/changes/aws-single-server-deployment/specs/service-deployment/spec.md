# Spec Delta

## Purpose

작은 실습 서버에서 검증된 버전을 반복 배포하고 외부에서 API를 사용할 수 있게 한다. 서버의 자원과 DB 데이터를 보존하며 실패를 식별하고, 비용·접근 범위에 영향을 주는 인프라 작업은 사용자 승인 범위 안에서 수행한다.

## ADDED Requirements

### Requirement: 검증한 main 버전 배포
시스템은 SHALL main에 반영된 버전을 서버 외부에서 빌드·검증하고 그 버전과 일치하는 실행 이미지를 단일 서버에 자동 배포한다.

#### Scenario: 정상 배포
- **WHEN** main push에 대한 빌드와 검증이 성공한다
- **THEN** 서버는 해당 커밋의 아키텍처 호환 이미지를 받아 실행하며 서버에서 소스 빌드를 수행하지 않는다

#### Scenario: 사전 검증 실패
- **WHEN** 빌드 또는 필수 테스트가 실패하거나 건너뛰어 완료되지 않는다
- **THEN** 신규 버전을 서버에 적용하지 않고 배포 작업을 실패로 보고한다

#### Scenario: 다른 브랜치의 변경
- **WHEN** main 이외 브랜치에 변경이 반영된다
- **THEN** 해당 변경만으로 배포 서버의 실행 버전을 교체하지 않는다

### Requirement: 제한된 자원에서 실행 유지
시스템은 SHALL 애플리케이션과 DB를 같은 서버에서 실행하고 1GiB의 스왑 및 자원 제한을 적용하며 재부팅 후 실행 상태를 복구한다.

#### Scenario: 최초 준비와 재부팅
- **WHEN** 승인받은 서버 준비가 완료되거나 서버가 재부팅된다
- **THEN** 1GiB 스왑과 정해진 컨테이너 자원·로그 제한이 유지되고 DB와 애플리케이션이 다시 시작된다

#### Scenario: 자원 부족
- **WHEN** 실제 서버에서 메모리 부족 또는 반복 재시작이 발생한다
- **THEN** 정상 배포로 완료 처리하지 않고 원인과 조정 필요성을 보고하며 추가 과금이 생기는 자원 증설은 확인 없이 수행하지 않는다

### Requirement: 외부 API 접근과 DB 데이터 유지
시스템은 SHALL 고정된 공인 주소에서 기존 [API 계약](../../../../../docs/api/api-contract.md)과 [Swagger 명세](../../../../../openspec/specs/api-documentation/spec.md)의 구현된 기능을 제공하고 DB 접근을 서버 내부로 제한한다.

#### Scenario: 외부 접근
- **WHEN** 배포 완료 후 다른 컴퓨터에서 서버에 접근한다
- **THEN** 공개된 주소로 Swagger·문서 JSON·API를 사용할 수 있고 DB 포트로는 외부에서 직접 연결할 수 없다

#### Scenario: 반복 배포와 상태 보존
- **WHEN** API로 상태를 저장한 후 애플리케이션 또는 DB 컨테이너를 재시작하거나 재배포한다
- **THEN** 기존 DB 볼륨을 재사용하고 저장된 상태를 유지하며 초기 데이터를 반복 삽입하지 않는다

### Requirement: 실패 식별과 복구
시스템은 SHALL 서버 명령 완료와 실제 서비스 상태를 확인해 배포 결과를 판정하며 직전 버전과 DB 상태를 구분해 복구한다.

#### Scenario: 명령 또는 상태 확인 실패
- **WHEN** 배포 명령이 실패·시간 초과되거나 서비스가 정상 상태에 도달하지 못한다
- **THEN** 배포를 실패로 표시하고 비밀값을 제외한 진단 정보와 직전 버전을 확인할 수 있다

#### Scenario: DB 변경이 없는 버전 복구
- **WHEN** 신규 애플리케이션이 실패하고 DB 스키마가 직전 버전과 호환됨을 확인한다
- **THEN** 직전 이미지를 다시 실행하고 상태 확인 결과를 보고하며 최초 배포처럼 직전 버전이 없으면 복구 성공을 주장하지 않는다

#### Scenario: DB 변경 후 실패
- **WHEN** DB 스키마 변경이 적용되었거나 적용 여부가 불명확한 상태에서 배포가 실패한다
- **THEN** 이미지 교체를 DB 복구로 간주하지 않고 실제 상태를 확인하며 데이터 삭제·migration 이력 강제 수정 없이 복구 조치를 결정한다

### Requirement: 승인 범위 안에서 인프라 관리
작업자는 MUST AWS 리소스 생성·설정 변경 전에 대상·설정·비용·접근 범위·데이터 영향을 제시하고 사용자 확인을 받은 범위만 실행한다.

#### Scenario: 최초 생성 또는 설정 변경
- **WHEN** EC2·디스크·고정 IP·네트워크·권한이나 서버 설정을 생성·변경하려 한다
- **THEN** 실제 조작 전에 해당 변경 묶음에 대해 사용자 확인을 받고 승인되지 않은 항목은 실행하지 않는다

#### Scenario: 승인된 자동 배포
- **WHEN** 사용자가 main 자동 배포의 연결 대상과 권한·동작 범위를 승인한 후 main이 변경된다
- **THEN** 승인된 서버에서 배포 절차를 실행하되 인프라 증설·권한 확대·데이터 삭제를 배포에 포함하지 않는다
