# Spec Delta

## Purpose

사용자 구분 없이 매장별로 공유하는 관심매장 찜 상태를 저장한다. 설정과 해제 및 반복 요청의 결과를 일관되게 제공하고, 잘못된 입력이나 존재하지 않는 매장은 상태를 변경하지 않고 거부한다.

## ADDED Requirements

### Requirement: 공유 찜 상태 저장
시스템은 SHALL [API 계약](../../../../../docs/api/api-contract.md)에 따라 매장의 공유 찜 상태를 요청 값으로 저장하고 저장 결과를 반환한다.

#### Scenario: 설정 후 해제
- **WHEN** 존재하는 매장에 찜 설정 후 해제를 요청한다
- **THEN** 각 요청 값이 저장되고 성공 응답에 반영된다

#### Scenario: 동일 값 반복
- **WHEN** 같은 매장에 같은 찜 값을 반복 요청한다
- **THEN** 상태를 반전하지 않고 요청한 값을 유지한다

#### Scenario: 다른 매장 정보 보존
- **WHEN** 찜 상태를 변경한다
- **THEN** 매장명과 이미지, 영업 상태, 거리 및 다른 매장의 상태를 변경하지 않는다

### Requirement: 잘못된 요청 거부
시스템은 SHALL API 계약의 입력 제약과 오류 응답을 적용하고, 거부한 요청으로 기존 상태를 변경하지 않는다.

#### Scenario: 잘못된 본문
- **WHEN** 본문·필수값 누락, null 필드, 불리언이 아닌 값, 잘못된 JSON 또는 객체가 아닌 본문을 전달한다
- **THEN** 계약에 맞는 400 오류 응답을 반환한다

#### Scenario: 유효하지 않은 ID
- **WHEN** 형식이 잘못되거나 양의 int64 범위를 벗어난 매장 ID를 전달한다
- **THEN** 계약에 맞는 400 오류 응답을 반환한다

#### Scenario: 매장 없음
- **WHEN** 유효한 ID에 해당하는 매장이 없다
- **THEN** 계약에 맞는 404 오류 응답을 반환한다

#### Scenario: 저장 실패
- **WHEN** 저장 중 예상하지 못한 서버 오류가 발생한다
- **THEN** 트랜잭션을 롤백하고 내부 정보를 노출하지 않는 500 오류 응답을 반환한다
