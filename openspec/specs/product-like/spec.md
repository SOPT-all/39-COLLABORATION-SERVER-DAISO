# product-like Specification

## Purpose

사용자 구분 없이 상품별로 공유하는 좋아요 상태를 저장한다. 설정·해제와 동일 값의 반복 요청을 일관되게 처리하고, 잘못된 입력이나 존재하지 않는 상품에 대한 요청은 기존 상태를 변경하지 않고 거부한다.

## Requirements

### Requirement: 공유 좋아요 저장
시스템은 SHALL [API 계약](../../../docs/api/api-contract.md#5-상품-좋아요-설정-및-해제)의 요청 값을 상품별 공유 상태로 저장하고 저장 결과를 반환한다.

#### Scenario: 설정과 해제
- **WHEN** 존재하는 상품에 좋아요 설정 후 해제를 요청한다
- **THEN** 각 요청 값이 저장되고 성공 응답에 반영된다

#### Scenario: 동일 값 반복
- **WHEN** 같은 상품에 같은 좋아요 값을 반복 요청한다
- **THEN** 상태를 반전하지 않고 요청한 값을 유지한다

#### Scenario: 다른 정보 보존
- **WHEN** 상품의 좋아요 상태를 변경한다
- **THEN** 상품의 나머지 정보와 다른 상품의 상태는 변경하지 않는다

### Requirement: 잘못된 요청 거부
시스템은 SHALL API 계약의 입력 제약과 오류 응답을 적용하며 거부한 요청으로 기존 상태를 변경하지 않는다.

#### Scenario: 잘못된 본문
- **WHEN** 본문·필수값 누락, null, 불리언이 아닌 값, 객체가 아닌 본문 또는 잘못된 JSON을 전달한다
- **THEN** 계약의 본문 오류 응답을 반환하며 저장하지 않는다

#### Scenario: 유효하지 않은 ID
- **WHEN** 상품 ID가 정수가 아니거나 양의 int64 범위를 벗어난다
- **THEN** 계약의 ID 오류 응답을 반환한다

#### Scenario: 상품 없음
- **WHEN** 유효한 ID에 해당하는 상품이 없다
- **THEN** 계약의 상품 없음 응답을 반환한다

#### Scenario: 저장 실패
- **WHEN** 저장 중 예상하지 못한 서버 오류가 발생한다
- **THEN** 트랜잭션을 롤백하고 내부 정보를 노출하지 않는 오류 응답을 반환한다

### Requirement: 요청 프로토콜 오류
시스템은 SHALL [공통 응답 계약](../../../docs/api/api-contract.md#23-공통-응답)의 메서드·미디어 타입 오류 응답을 적용하고 기존 HTTP 상태와 관련 응답 헤더를 유지한다.

#### Scenario: 지원하지 않는 메서드
- **WHEN** 상품 좋아요 경로를 지원하지 않는 HTTP 메서드로 호출한다
- **THEN** 계약의 메서드 오류 응답과 허용 메서드 헤더를 반환한다

#### Scenario: 지원하지 않는 Content-Type
- **WHEN** 지원하지 않는 Content-Type으로 요청한다
- **THEN** 계약의 미디어 타입 오류 응답과 지원 미디어 타입 헤더를 반환한다
